# Incremental research store, v1
This stores raw response batches and closed-bar close values in a local SQLite DB. It deduplicates keys, retains originals on changed close and records close revisions, checks ordering and reports gaps between downloaded batches; each write is transactional. No source other than experimental BTCUSDT 1h. New rows are explicitly HISTORICAL BACKFILL, never live. Tests use synthetic data. The sample DB was seeded only from the previously fetched, time-conflicted replay; timestamps are untrusted and must be reconciled.

LIMITATIONS: pull fetches the latest up to 1000 bars, not full paginated catch-up. Existing bars can change fields other than close; raw batches preserve them but no full-field reconciliation is performed. No signal state/outcome table, no automated backup, no cloud scheduler, no Telegram integration, no license resolution, no MT5 equivalence. Running this once does not create a continuous system. SQLite file must be snapshotted via SQLite backup API. Do not publish raw data or private identifiers to public GitHub. The environment clock and API server date agree with each other and other HTTP Date headers but conflict with the trusted session date; independently reconcile before interpreting timestamps.
