# ALINA catch-up research pilot v1

BTCUSDT 1h public Binance read-only REST. A job has a fixed UTC [start,end) hour-aligned range. Pages of at most 1,000 bars, exact expected timestamps and count, one transaction per page, cursor resumes after restart; partial or gapped pages and changed full-row data fail closed. Source responses retained with hashes; original rows never overwritten. `--max-pages` limits work per invocation. No orders, no live signals. Rights for data remain unknown; keep sample privately for research.

Synthetic tests: `python3 -m unittest -v`. Remote two-call resume test completed 2026-09-01 through 2026-11-01 UTC (1,464 bars, 1,000 + 464), SQLite integrity OK; separate 72-bar sample 2026-11-01 through 2026-11-04. Both intervals precede the trusted session date. Provider and machine timestamps report 2026-11-23, conflicting with trusted session date 2026-11-22; retrieval timestamp and claims about current market remain untrusted. Provider close-time check alone is not independent clock verification.

Remaining: not a scheduler, no automatic Drive backup, no live observation, no outcomes, no retry policy or independent byte-level source validation, no MT5 comparison. Known risk: full JSON equality may treat harmless provider formatting changes as a revision, deliberately failing closed; overlapping revisions require manual reconciliation and original is retained. Independent jobs may overlap. The ingestion page is captured only when it passes all validation and commits; HTTP errors and malformed pages are not persisted. Source can change or omit data; internal continuity is not proof of external truth. SQLite backup API used for snapshots; WAL files must not be copied while active. No personal details or credentials included.
