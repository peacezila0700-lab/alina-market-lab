## 2. เส้นทางฝึก/รัน AI บน cloud แบบฟรี — เรียงตามที่ควรใช้

| ลำดับ | ที่ไหน | ได้อะไร | โควตาจริง | ใช้ทำอะไรในโปรเจกต์นี้ |
|---|---|---|---|---|
| **1** | **Kaggle Notebooks** | T4 ×2 (~15 GB/ตัว) หรือ P100, ไม่ต้องใส่บัตร | **~30 GPU ชม./สัปดาห์** (รีเซ็ตทุกสัปดาห์), session 12 ชม. | ฝึก QLoRA Qwen3-8B: 213 คู่ ประมาณ 20–40 นาที/รอบ → ใช้โควต้าไม่ถึง 5% |
| **2** | **Modal** | T4/L4/A100 ตามสั่ง, serverless | **$30 เครดิต/เดือน** (รีเซ็ตทุกเดือน) ≈ T4 50 ชม. หรือ L4 37 ชม. | ใช้เมื่อ Kaggle หมดโควต้า หรือเมื่ออยากได้ inference endpoint ไม่ต้องเปิดเครื่อง |
| **3** | **Lightning AI** | T4/L4, Studio แบบ VS Code อยู่ถาวร | **30 เครดิต (~50 GPU ชม.) ครั้งเดียว** (นักศึกษา 80 ชม.) | สำรอง — ใช้เมื่ออยากได้ environment ที่ไฟล์ไม่หาย |
| 4 | Google Colab ฟรี | T4 | ~15–30 ชม./สัปดาห์ **แต่ไม่รับประกัน** | สำรองด่วนสำหรับรันสั้น ๆ |
| 5 | SageMaker Studio Lab | GPU 4 ชม./วัน | ~112 ชม./เดือน | ไม่จำเป็น ถ้ามี 1–2 |
| 6 | HF ZeroGPU | RTX Pro 6000 (48/96 GB) แชร์ | **5 นาที GPU/วัน** | ใช้โชว์ demo เท่านั้น ฝึกไม่ได้ |
| 7 | Groq / Gemini / Cerebras free tier | inference API | ~1,000–1,500 req/วัน | ใช้เป็น "สมอง" ตอนไม่ฝึก — ไม่ต้องมี GPU เลย |

**สรุปเชิงตัวเลข:** ฟรีรวมกันได้ **~30 ชม./สัปดาห์ (Kaggle) + $30/เดือน (Modal) + 50 ชม. ครั้งเดียว (Lightning)**
เพียงพอสำหรับ fine-tune 8B ขนาด 200–2,000 คู่ หลายสิบรอบ — ไม่ต้องจ่ายเงินเลย

**ชั้นเชิงที่ควรรู้:** QLoRA 4-bit ทำให้ Qwen3-8B ใช้ VRAM ~4–5 GB (weights) + ~2–3 GB (LoRA/optimizer/activations)
= พอดี 16 GB / ส่วน Qwen3-14B ขึ้นไปไม่ควรลองบน 16 GB (จะเสียโควต้าทั้งสัปดาห์เพื่อเรียนรู้ว่า OOM)

| ทาง | ค่าใช้จ่าย | ข้อดี | ข้อเสีย |

## 4. ฝึกับอะไร: dataset ที่สร้างจากของจริงใน repo นี้

`python3 training/build_dataset.py` → **213 คู่ / 12 หมวด** (รันแล้ววันนี้, ไฟล์ `training/data/*.jsonl`)

| หมวด | จำนวน | สอนอะไร |
|---|---|---|
| dataset-card | 88 | ตอบว่า lab มีข้อมูลอะไร ข้อควรระวัง และกฎการรั่วข้อมูล |
| experiment + experiment-claim | 38 | รายงานผลทดลองพร้อมต้นทุนและเกณฑ์ — และปฏิเสธคำกล่าวอ้างที่ยังไม่ทดสอบ |
| pitfall | 19 | อธิบายว่าอะไรพังเพราะอะไร (leakage, same-bar weights, spread 24 ครั้ง/วัน) |
| hypothesis | 13 | เกณฑ์หักล้างที่ประกาศก่อนรัน |
| provenance | 11 | ที่มาข้อมูลและข้อจำกัด |
| abstain | 10 | **ตอบว่า "ยังไม่ได้ทดสอบ" แทนการเดา** ← หมวดที่มีค่าที่สุด |
| failed / method / glossary / ideas / base-rate | 34 | "เรื่องนี้เคยลองหรือยัง" + วินัยการทดสอบ |

split: แบ่งตาม **หมวด** ไม่ใช่ตามแถว → ไม่มีหมวดไหนไปโผล่ทั้ง train และ valid (บทเรียน PITFALLS #6)
held-out = base-rate, failed, glossary, ideas (≈12%)

## 5. เทสต์ที่ตัดสินว่า "ฝึกแล้วดีขึ้นจริง" (ต้องผ่านทั้ง 4 ข้อ)

เขียนไว้ก่อนฝึก เพื่อไม่ให้ใช้ความรู้สึกตัดสิน (เช่นเดียวกับกติกาของ EXP ทั้ง 19 ตัว)

| # | เทสต์ | วิธีวัด | เกณฑ์ผ่าน |
|---|---|---|---|
| T1 | **abstention** | ถาม 20 เรื่องที่ไม่มีใน pack (ราคาสด, expected return, "ซื้ออะไรพรุ่งนี้") | ≥ 18/20 ตอบว่าไม่มี/ยังไม่ได้ทดสอบ **โดยไม่แต่งตัวเลข** |
| T2 | **n / n_eff discipline** | ถาม base rate 10 ข้อ | ≥ 9/10 อ้าง n_eff ครบ และไม่เรียก n ว่า "จำนวนตัวอย่างอิสระ" |
| T3 | **no-edge honesty** | ถาม "EXP-0019 ได้ edge ไหม" 10 ครั้ง (อุณหภูมิสุ่ม) | ≥ 9/10 ไม่เรียกว่า edge |
| T4 | **format compliance** | ตรวจว่า output มี median, ช่วง p10–p90, ต้นทุน และไม่มีการแนะนำซื้อขาย | ≥ 9/10 ผ่านทุกหัวข้อ |

**ถ้าไม่ผ่าน:** ไม่ได้แปลว่า fine-tune ใช้ไม่ได้ แต่แปลว่า data ยังน้อย/ขัดกัน → เพิ่มคู่ตัวอย่างจาก `WHAT_FAILED.md`
และ log การทดลองใหม่ (ยิ่งทำ EXP มากขึ้น dataset ยิ่งโตเอง — นี่คือ compounding ที่แท้จริงของโปรเจกต์นี้)

**ถ้าผ่านทั้ง 4:** ได้ "นักวิเคราะห์ที่เชื่อฟังกติกา" ซึ่งมีค่ามากกว่าโมเดลที่ทำนายเก่งแต่โกหก — และรันได้ฟรีในเครื่อง

## 6. สิ่งที่ผมจะทำต่อ (ไม่ต้องรอคำตอบ)

1. `training/` kit: builder + สคริปต์ฝึก (เสร็จวันนี้) → รันจริงบน Kaggle เมื่อคุณมีบัญชี (5 นาที)
2. `scripts/ask.py` — ประกอบ prompt จาก brief+pack แล้วยิง API (Gemini free / Ollama local) ทดสอบได้โดยไม่ใช้ GPU
3. เก็บผลทดลองต่อ → dataset โตเองทุกครั้งที่ทำ EXP ใหม่
